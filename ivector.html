i-Vectors

This page explains what an i-vector is, how it is computed, and how the classes in this package (IvectorExtractor, OnlineIvectorEstimationStats, OnlineIvectorExtractor) implement the computation. The math follows kaldi's ivector/ivector-extractor.h, ivector/ivector-extractor.cc and online2/online-ivector-feature.cc exactly; the port is validated frame-by-frame against kaldi (see tests/parity/parity_ivector.py).

What problem i-Vectors solve

The acoustic features of the same word depend strongly on who is speaking and how it was recorded (microphone, room, channel). A speech recognizer trained on many speakers therefore sees each phone smeared across many slightly-different feature distributions.

An i-vector is a single, low-dimensional vector (typically 40–400 dimensions) that summarizes the speaker and channel of one utterance. The recognizer's acoustic model takes it as an extra input and can compensate for the mismatch. It is called total variability modeling: one latent space carries both speaker and channel variability (Dehak et al., 2011).

The generative model

Notation (kaldi uses SGMM-style letters throughout its code):

  • \(D\) — feature dimension (e.g. 40 MFCCs after transform)

  • \(I\) — number of Gaussians in the universal background model (UBM)

  • \(S\) — i-vector dimension

  • \(\mathbf{x}\) — one feature frame

Each UBM Gaussian \(g\) has a mean \(\mathbf{m}_g\) and (diagonal) covariance \(\Sigma_g\). When speaker \(\mathbf{y}\) is present, the mean of Gaussian \(g\) is shifted linearly:

\[\boldsymbol{\mu}_g(\mathbf{y}) = \mathbf{m}_g + M_g \mathbf{y},\]

where \(M_g\) is a \(D \times S\) matrix ("mean subspace", M_ in the code) and \(\mathbf{y}\) is the i-vector. The prior over i-vectors is standard normal except for the first dimension, which has offset \(o\) (prior_offset_, e.g. 33.1 — this encodes the global offset of the adapted means so the subspace can stay zero-mean):

\[\begin{split}p(\mathbf{y}) = \mathcal{N}\!\left(\begin{bmatrix}o\\ \mathbf{0}\end{bmatrix}, I\right).\end{split}\]

At test time we never know \(\mathbf{y}\); we compute its posterior mean from the features of an utterance — that estimate is the i-vector.

How it is computed

Step 1: Gaussian posteriors

Every frame is assigned soft posteriors over the \(I\) Gaussians using the UBM (a diagonal-covariance GMM, e.g. final.dubm):

\[\gamma_{tg} = \frac{p_g\,\mathcal{N}(\mathbf{x}_t; \mathbf{m}_g, \Sigma_g)} {\sum_{g'} p_{g'}\,\mathcal{N}(\mathbf{x}_t; \mathbf{m}_{g'}, \Sigma_{g'})}.\]

In practice the posterior is pruned: keep the top-num_gselect Gaussians and/or drop entries below min_post of the total (vector_to_posterior_entry()).

Step 2: sufficient statistics

Accumulate per-Gaussian zeroth- and first-order statistics over the utterance (IvectorExtractorUtteranceStats):

\[\gamma_g = \sum_t \gamma_{tg}, \qquad \mathbf{X}_g = \sum_t \gamma_{tg}\, \mathbf{x}_t.\]

Step 3: the posterior over \(\mathbf{y}\)

Marginalizing the Gaussians, the posterior \(p(\mathbf{y}\,|\,\text{utt})\) is Gaussian with precision and linear term

\[\begin{split}\Lambda = I + \sum_g \gamma_g\, M_g^\top \Sigma_g^{-1} M_g, \qquad \boldsymbol{\ell} = \sum_g M_g^\top \Sigma_g^{-1} \mathbf{X}_g + \begin{bmatrix}o\\ \mathbf{0}\end{bmatrix},\end{split}\]

and therefore

\[\hat{\mathbf{y}} = \Lambda^{-1} \boldsymbol{\ell}.\]

The code precomputes \(U_g = M_g^\top \Sigma_g^{-1} M_g\) and \(\Sigma_g^{-1} M_g\) once (ComputeDerivedVars) so that estimating an i-vector is only a few matrix-vector products plus one linear solve.

Step 4: solving for \(\hat{\mathbf{y}}\)

Two options:

  • Exact: invert \(\Lambda\) (or solve the linear system). Used by IvectorExtractor.compute_ivector().

  • Conjugate gradient, warm-started from the previous estimate — the streaming choice. OnlineIvectorEstimationStats.get_ivector() runs LinearCgd for num_cg_iters iterations (kaldi suggests 15; pass a negative value to solve exactly). Warm starts matter: every re-estimate begins near the solution, so a handful of iterations suffices.

Streaming estimation

In online decoding the i-vector is re-estimated every ivector_period frames (e.g. 10) using all frames seen so far. Rather than re-accumulating statistics from scratch, OnlineIvectorEstimationStats maintains \(\Lambda\) and \(\boldsymbol{\ell}\) incrementally: each frame adds \(\gamma_{tg} U_g\) and \(M_g^\top \Sigma_g^{-1} (\gamma_{tg}\mathbf{x}_t)\).

Prior scaling (``max_count``). As the utterance grows, the data term overwhelms the unit prior and long utterances produce atypical ("too confident") i-vectors. With max_count (vosk uses 100) the prior term is weighted by \(\max(n, c)/c\), where \(n\) is the frame count and \(c\) is max_count: up to \(c\) frames nothing changes, beyond it the prior pulls the estimate back toward typical.

Output convention. Both kaldi's ivector-extract-online and its runtime class OnlineIvectorFeature remove the prior offset from the first dimension of the output (y[0] -= prior_offset) so the vector is approximately zero-mean — this is the vector the acoustic model expects. OnlineIvectorExtractor follows the same convention (the raw estimate keeps the offset internally as the CG starting point).

The full pipeline of a vosk model

OnlineIvectorExtractor reproduces kaldi's OnlineIvectorFeature dataflow:

raw MFCC ──┬── running CMVN → splice(±3) → lda (final.mat) → UBM posteriors
           │                                              │
           └── splice(±3) → lda ──────────────────────────┴─→ stats → y-hat

Note the asymmetry (it is kaldi's, deliberately): the UBM posteriors are computed on the CMVN-normalized chain, while the first-order statistics accumulate the un-normalized transformed features (unless the online_cmvn_iextractor option is set; vosk's models leave it off).

Model files

A trained i-vector model directory (e.g. a vosk model's ivector/):

File

Role

final.ie

The extractor: \(M_g\), \(\Sigma_g^{-1}\), prior_offset (and optionally weight projections \(\mathbf{w}_g\))

final.dubm

The UBM (diagonal GMM) used for posteriors

final.mat

LDA-like linear transform of spliced features

global_cmvn.stats

Global CMVN stats [2, D+1], seeds running CMVN

splice.conf

Splice context (usually --left-context=3 --right-context=3)

online_cmvn.conf

Running-CMVN options (may be empty ⇒ defaults)

Python example

import kaldi_hmm_gmm as khg
import kaldi_native_io

extractor = khg.IvectorExtractor.read("ivector/final.ie")
ubm = khg.read_diag_gmm("ivector/final.dubm")
lda = kaldi_native_io.FloatMatrix.read("ivector/final.mat").numpy()
gs = kaldi_native_io.DoubleMatrix.read("ivector/global_cmvn.stats").numpy()

cfg = khg.OnlineIvectorExtractorConfig(
    left_context=3, right_context=3,
    lda_mat=lda, global_cmvn_stats=gs,
    max_count=100, num_cg_iters=15, ivector_period=10)

eng = khg.OnlineIvectorExtractor(cfg, extractor, ubm)
eng.accept_features(mfcc)          # [T, 40] float32, from int16-scale audio
eng.flush()                        # end of utterance
print(eng.get_ivectors().shape)    # [ceil(T/10), ivector_dim]

For a batch/offline computation with explicit posteriors, see IvectorExtractorUtteranceStats and IvectorExtractor.compute_ivector().
