Force-align one utterance (kaldi's gmm-align-compiled core).

Adds the transition probabilities to the training graph (AddTransitionProbs with transition_scale/self_loop_scale) and runs the Viterbi alignment in a single C++ call. Mutates the graph in place (same as kaldi's gmm-align-compiled); pass a copy to reuse it afterwards.

Returns (num_done, num_error, num_retried, tot_like, frame_count, alignment, words): the five counters are INPUTS that get incremented (kaldi's accumulating-table semantics) -- omit them to get this utterance's contributions only, or thread running totals through a loop. alignment is transition-ids.

Parameters:

  • config -- Alignment beams (AlignConfig).

  • utt -- Utterance id (for log messages).

  • acoustic_scale -- Acoustic scale used in the alignment.

  • transition_scale -- Transition-probability scale.

  • self_loop_scale -- Self-loop versus non-self-loop log-prob scale.

  • trans_model -- Transition model (TransitionModel; needed for AddTransitionProbs).

  • fst -- Per-utterance training graph; mutated in place.

  • decodable -- Scores (DecodableInterface).

align_utterance adds the transition probabilities to the training graph (AddTransitionProbs) and runs the Viterbi alignment in a single C++ call. It mutates the graph in place (same as kaldi's gmm-align-compiled) and returns (num_done, num_error, num_retried, tot_like, frame_count, alignment, words); alignment holds transition-ids.

Typical use:

cfg = khg.AlignConfig(beam=10.0, retry_beam=40.0)
num_done, num_error, _, like, frames, alignment, words = khg.align_utterance(
    config=cfg, utt="utt", acoustic_scale=0.1,
    transition_scale=1.0, self_loop_scale=0.1,
    trans_model=tm, fst=graph, decodable=decodable)

kaldi_hmm_gmm.lattice_best_path(lat: kaldi_hmm_gmm.lib._kaldi_hmm_gmm.Lattice, lm_scale: SupportsFloat = 1.0, acoustic_scale: SupportsFloat = 1.0) → tuple[bool, list[int], list[int], float]

1-best of a lattice under lm/acoustic scaling (kaldi's lattice-best-path).

Minimizes lm_scale * graph_cost + acoustic_scale * acoustic_cost. On the lattices returned by decode_utterance_lattice_faster() (acoustic costs already divided by the decode acoustic scale), use acoustic_scale=1.0 and sweep lm_scale for lmwt scoring.

Parameters:

  • lat -- Input lattice (kaldifst.Lattice).

  • lm_scale -- Weight of the graph cost (kaldi --lm-scale).

  • acoustic_scale -- Weight of the acoustic cost (kaldi --acoustic-scale).

Returns:

(ok, alignment, words, like); ok is False when the lattice has no complete path (outputs empty).

decode_utterance_* returns (ok, alignment, words, like, lat) where lat is the lattice exactly as kaldi writes it (acoustic costs divided by the acoustic scale); feed it to lattice_best_path for 1-best under lm/acoustic scaling (kaldi's lattice-best-path). lat is a Lattice (the fst::VectorFst<fst::LatticeArc> returned by the decoder); lattice_best_path also accepts kaldifst.Lattice objects.

class kaldi_hmm_gmm.DecodableInterface(self: kaldi_hmm_gmm.lib._kaldi_hmm_gmm.DecodableInterface)

Scoring interface every decoder consumes.

This is kaldi's DecodableInterface. It answers one question: how likely is transition-id ``index`` at frame ``frame``? Implement it in Python to plug any acoustic model into kaldi_hmm_gmm's alignment/decoding functions (a pybind11 trampoline keeps virtual dispatch on the Python side).

Indices are one-based (openfst convention, 0 is epsilon).

Lifetime: decoders borrow the decodable without owning it -- keep the Python object alive for the whole decode.

See also

class kaldi_hmm_gmm.TransitionInformation(self: kaldi_hmm_gmm.lib._kaldi_hmm_gmm.TransitionInformation)

Transition-model interface used by the alignment/decoding functions.

kaldi's TransitionInformation: provides the tid->pdf map and per-transition-id queries. Implement it in Python to use decode_utterance_lattice_faster() / decode_utterance_lattice_simple() with an alternative transition model; TransitionModel implements the same interface in C++ (and is what align_utterance() requires, for AddTransitionProbs).

Note: transition_id_to_pdf_array() must return the whole map on every call (the trampoline caches it; that cached reference is what decodables keep).

Implement the pure virtual methods in a subclass.

DecodableInterface and TransitionInformation accept Python subclasses (a pybind11 trampoline keeps virtual dispatch on the Python side), so custom acoustic scorers or transition models can be plugged into the alignment/decoding functions.
