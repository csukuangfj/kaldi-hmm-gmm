◆ AddSelfLoops()

void khg::AddSelfLoops ( const TransitionModel & trans_model,
const std::vector< int32_t > & disambig_syms,
float self_loop_scale,
bool reorder,
bool check_no_self_loops,
fst::VectorFst< fst::StdArc > * fst )

Adds self-loops to an FST that was built without them.

For context, this is the last step of building HCLG-style graphs from the H transducer of GetHTransducer(). Expands an FST that has been built without self-loops, and adds the self-loops (it also needs to modify the probability of the non-self-loop ones, as the graph without self-loops was created in such a way that it was stochastic). Concretely, for every state with a transition-state, a self-loop is added with cost \(-s_{\mathrm{sl}} \log p_{\mathrm{sl}}\) and the other out-arcs (and the final weight) of the state are multiplied by the forward probability mass, i.e. their cost is increased by \(-s_{\mathrm{sl}} \log (1 - p_{\mathrm{sl}})\), where \(p_{\mathrm{sl}}\) is the self-loop probability and \(s_{\mathrm{sl}}\) is self_loop_scale. Note that the disambig_syms will be empty in some recipes (e.g. if you already removed the disambiguation symbols). This function will treat numbers over 10000000 (kNontermBigNumber) the same as disambiguation symbols, assuming they are special symbols for grammar decoding.

Parameters
trans_model[in] Transition model
disambig_syms[in] Sorted, uniq list of disambiguation symbols, required if the graph contains disambiguation symbols but only needed for sanity checks.
self_loop_scale[in] Transition-probability scale for self-loops; see the scale conventions in the file documentation.
reorder[in] If true, reorders the transitions (the transition-id of a forward transition is placed on the arc entering its destination state, before the self-loop; Dan-style graphs). You'll normally want this to be true.
check_no_self_loops[in] If true, it will check that there are no self-loops in the original graph; you'll normally want this to be true. If false, it will allow them, and will add self-loops after the original self-loop transitions, assuming reorder==true... this happens to be what we want when converting normal to unconstrained chain examples. WARNING: this was added in 2018; if you get a compilation error, add this as 'true', which emulates the behavior of older code.
fst[in, out] The FST to be modified.

◆ AddTransitionProbs()

void khg::AddTransitionProbs ( const TransitionModel & trans_model,
const std::vector< int32_t > & disambig_syms,
float transition_scale,
float self_loop_scale,
fst::VectorFst< fst::StdArc > * fst )

Adds transition-probs to the graph.

Adds transition-probs, with the supplied scales (see the scale conventions in the file documentation), to the graph. Every arc labeled with a transition-id gets its weight multiplied by the corresponding transition probability: if transition_scale and self_loop_scale are equal this is just \(s \log p\); otherwise self-loops get \(s_{\mathrm{sl}} \log p\) and non-self-loop transitions get \(s_{\mathrm{sl}} \log(1 - p_{\mathrm{sl}}) + s_t \log \tilde{p}\) (the renormalized scheme of GetHTransducer()/AddSelfLoops()). In all cases the log-probs are simply added to what the arcs already carry.

Useful if you want to create a graph without transition probs, then possibly train the model (including the transition probs) but keep the graph fixed, and add back in the transition probs. It assumes the fst has transition-ids on it. It is not an error if the FST has no states (nothing will be done). Note that in the standard training pipeline this is called at alignment time (the training graphs are compiled with both scales set to 0, because the transition probs change at every iteration while the graphs stay fixed); applying it to a graph that already has transition probs applies them a second time, which matches kaldi and is intentional - do not "fix" it.

Parameters
trans_model[in] The transition model
disambig_syms[in] A list of disambiguation symbols, required if the graph has disambiguation symbols on its input but only used for checks.
transition_scale[in] A scale on transition-probabilities apart from those involving self-loops.
self_loop_scale[in] A scale on self-loop transition probabilities.
fst[in, out] The FST to be modified.

◆ ClusterKMeans()

float khg::ClusterKMeans ( const std::vector< Clusterable * > & points,
int32_t num_clust,
std::vector< Clusterable * > * clusters_out,
std::vector< int32_t > * assignments_out,
const ClusterKMeansOptions & cfg = ClusterKMeansOptions() )

A K-means-like clustering algorithm.

ClusterKMeans is a K-means-like clustering algorithm. It starts with pseudo-random initialization of points to clusters and uses RefineClusters to iteratively improve the cluster assignments. It does this for multiple iterations and picks the result with the best objective function.

ClusterKMeans implicitly uses Rand(). It will not necessarily return the same value on different calls. Use sRand() if you want consistent results. The algorithm used in ClusterKMeans is a "k-means-like" algorithm that tries to be as efficient as possible. Firstly, since the algorithm it uses includes random initialization, it tries the whole thing cfg.num_tries times and picks the one with the best objective function. Each try, it does as follows: it randomly initializes points to clusters, and then for cfg.num_iters iterations it calls RefineClusters(). The options to RefineClusters() are given by cfg.refine_cfg. Calling RefineClusters once will always be at least as good as doing one iteration of reassigning points to clusters, but will generally be quite a bit better (without taking too much extra time).

Parameters
points[in] Points to be clustered (must be all non-NULL).
num_clust[in] Number of clusters requested (it will always return exactly this many, or will fail if num_clust > points.size()).
clusters_out[out] May be NULL; if non-NULL, should be empty when called. Will be set to a vector of statistics corresponding to the output clusters.
assignments_out[out] May be NULL; if non-NULL, will be set to a vector of same size as "points", which says for each point which cluster it is assigned to.
cfg[in] Configuration class specifying options to the algorithm.
Returns
Returns the objective function improvement \(\Delta\) versus everything being in the same cluster, i.e. \(\sum_c \mathrm{Objf}(c) - \mathrm{Objf}(\mathrm{all\ points})\).

◆ GetHTransducer()

fst::VectorFst< fst::StdArc > * khg::GetHTransducer ( const std::vector< std::vector< int32_t > > & ilabel_info,
const ContextDependencyInterface & ctx_dep,
const TransitionModel & trans_model,
const HTransducerConfig & config,
std::vector< int32_t > * disambig_syms_left )

Returns the H transducer; result owned by caller.

Caution: our version of the H transducer does not include self-loops; you have to add those later (see AddSelfLoops()). The H transducer has on the input transition-ids, and also possibly some disambiguation symbols, which will be put in disambig_syms. The output side contains the identifiers that are indexes into "ilabel_info" (these represent phones-in-context or disambiguation symbols). The ilabel_info vector allows GetHTransducer to map from symbols to phones-in-context (i.e. phonetic context windows). Any singleton symbols in the ilabel_info vector which are not phones, will be treated as disambiguation symbols. [Not all recipes use these]. The output "disambig_syms_left" will be set to a list of the disambiguation symbols on the input of the transducer (i.e. same symbol type as whatever is on the input of the transducer).

The transition costs are baked ONLY on the HMM transition arcs: an arc labeled with a transition-id carries cost \(-s_t \log \tilde{p}\), where \(\tilde{p}\) is the transition probability renormalized to exclude the self-loop probability mass of its state (see TransitionModel::GetTransitionLogProbIgnoringSelfLoops) and \(s_t\) is config's transition_scale. The context-expansion arcs (labeled on the output side with indexes into ilabel_info) have weight zero. This matches kaldi; the cost placement is intentional.

Parameters
ilabel_info[in] The ilabel info: element i is the phone-in-context (or singleton disambiguation symbol) that output symbol i stands for.
ctx_dep[in] The phonetic decision tree; maps pdf-classes to pdf-ids.
trans_model[in] The transition model; provides the transition-ids and the transition probabilities.
config[in] Configuration object; see HTransducerConfig.
disambig_syms_left[out] Set to the list of disambiguation symbols appearing on the input side of the transducer.
Returns
The H transducer (ownership passed to the caller).

GetStubMap is used in tree-building functions to get the initial to-states map, before the decision-tree-building process. It creates a simple map that splits on groups of phones. For the set of phones in phone_sets[i] it creates either: if share_roots[i] == true, a single leaf node, or if share_roots[i] == false, separate root nodes for each HMM-position (it goes up to the highest position for any phone in the set, although it will warn if you share roots between phones with different numbers of states, which is a weird thing to do but should still work. Maximum A Posteriori estimation of the model.

Interpolates the ML estimates above with the old parameters using the taus from config:

\[ \hat w_j = \frac{o_j + \tau_w w_j}{\sum_k o_k + \tau_w}, \qquad \hat\mu_j = \frac{s^{(1)}_j + \tau_\mu \mu_j}{o_j + \tau_\mu}, \]

and the variance is computed around the updated mean and mixed with the old variance as

\[ \hat\sigma^{2}_j = \frac{o_j \tilde\sigma^{2}_j + \tau_\sigma \sigma^{2}_j}{o_j + \tau_\sigma}, \]

where \(\tilde\sigma^{2}_j\) is the data variance around \(\hat\mu_j\). The weight tau is applied per pdf (state), not per Gaussian. As in the ML update, only the groups selected by flags are transferred back to the model.

ML re-estimation of a DiagGmm from accumulated statistics.

For each component \(j\) with occupancy \(o_j\), first-order statistic \(s^{(1)}_j\) and second-order statistic \(s^{(2)}_j\) the estimates are

\[ \hat\mu_j = \frac{s^{(1)}_j}{o_j}, \qquad \hat\sigma^{2}_j = \frac{s^{(2)}_j}{o_j} - \hat\mu_j^{2}, \qquad \hat w_j = \frac{o_j}{\sum_k o_k}, \]

where the variance is floored at config.min_variance (or at config.variance_floor_vector if set). A component is updated only if its occupancy exceeds config.min_gaussian_occupancy and its weight exceeds config.min_gaussian_weight; otherwise its weight is floored, or the component is removed entirely if config.remove_low_count_gaussians is true (never removing the last component). If only the variances are being updated, the estimate is computed around the old mean so that the mean does not move.

Update using the DiagGmm: exponential form. Sets, does not increment, objf_change_out, floored_elements_out and floored_gauss_out.
