Detailed Description

Maximum-likelihood and MAP estimation for diagonal-covariance GMMs.

This file is copied/modified from ../kaldi/src/gmm/mle-diag-gmm.h.

It provides the estimation side of DiagGmm training:

  • Option structs: MleDiagGmmOptions (variance floor, minimum occupancy/weight, removal of low-count Gaussians) and MapDiagGmmOptions (the MAP taus for means, variances and weights).
  • AccumDiagGmm: accumulators for the per-component zero-, first- and second-order statistics of a single DiagGmm.
  • The update functions MleDiagGmmUpdate() (ML re-estimation) and MapDiagGmmUpdate() (MAP adaptation), plus MlObjective() which evaluates the data log-likelihood that the ML update maximizes.

The statistics are accumulated in double precision. For a component \(j\) and frames \(t\) with posteriors \(\gamma_{t,j}\):

\[ o_j = \sum_t \gamma_{t,j}, \qquad s^{(1)}_j = \sum_t \gamma_{t,j} \, x_t, \qquad s^{(2)}_j = \sum_t \gamma_{t,j} \, x_t^{2} \]

(elementwise square; stored in AccumDiagGmm::occupancy(), mean_accumulator() and variance_accumulator() respectively).

The ML update replaces the parameters by

\[ \hat\mu_j = \frac{s^{(1)}_j}{o_j}, \qquad \hat\sigma^{2}_j = \frac{s^{(2)}_j}{o_j} - \hat\mu_j^{2}, \qquad \hat w_j = \frac{o_j}{\sum_k o_k}, \]

with variance flooring and gating/removal of low-count components; the MAP update interpolates the same estimates with the old parameters using the taus from MapDiagGmmOptions. Only the parameter groups selected by the flags argument are updated (and transferred back to the model).

GMM update flags

The flags arguments select the parameter groups to update. They are built from GmmUpdateFlags (defined in model-common.h, bit values shown below) using a bitwise OR; the corresponding kaldi command-line option is a subset of the string "mvwt" (e.g. --update-flags=mvw):

  • kGmmMeans = 0x001 (kaldi 'm'): update the means.
  • kGmmVariances = 0x002 (kaldi 'v'): update the variances (requires the means to be accumulated too).
  • kGmmWeights = 0x004 (kaldi 'w'): update the mixture weights.
  • kGmmTransitions = 0x008 (kaldi 't'): transition parameters; not really part of the GMM and not used by the functions in this file.
  • kGmmAll = 0x00F (kaldi 'a'): all of the above.

The concrete typedef of the flag word is GmmFlagsType; see also StringToGmmFlags() and AugmentGmmFlags() in model-common.h.

Typical usage (mirrors kaldi's gmm-acc-stats-ali + gmm-est): create an AccumDiagGmm with the same flags as the update, fill it with AccumulateFromDiag() (or AccumulateFromPosteriors() / AccumulateForComponent()), then call MleDiagGmmUpdate() and finally DiagGmm::ComputeGconsts().
