Detailed Description

Per-phone HMM topology: states, pdf-classes, transitions and final probabilities.

This file is copied/modified from kaldi/src/hmm/hmm-topology.h.

This module provides the HmmTopology class, which stores one topology entry (a vector of HmmState) for each phone: the states of the phone's HMM, the pdf-class attached to each state (a pdf-class is later mapped to an actual pdf-id by the phonetic decision tree), the transitions out of each state with their default (pre-training) transition probabilities, and the final-probability of the last state. The constant kNoPdf marks nonemitting states, which have no pdf attached.

The API consists of:

  • The HmmState structure (a single HMM state: pdf-classes, transitions).
  • Read()/Write() of the kaldi text (or binary) format; the topology is always stored without any symbol table.
  • Queries used by tree building and by the TransitionModel: TopologyForPhone(), NumPdfClasses(), GetPhoneToNumPdfClasses(), MinLength(), GetPhones(), IsHmm().

Usage notes: every phone in the system must be covered by exactly one <TopologyEntry> block; the first state of an entry is its start state and its last state must be nonemitting with no output transitions (its exit probability is one). IsHmm() distinguishes "normal" topologies (same pdf-class for self-loops and forward transitions) from the more general kind used e.g. by chain models.

See also kaldi/src/hmm/hmm-topology.h.
