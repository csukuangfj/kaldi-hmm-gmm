Detailed Description

Compilation of training graphs (per-utterance FSTs labeled with transition-ids).

This file is copied/modified from kaldi/src/decoder/training-graph-compiler.h.

This module provides TrainingGraphCompiler, the class behind kaldi's compile-train-graphs binary: it combines the lexicon FST (L), the phonetic decision tree (ContextDependency) and the TransitionModel into a context-dependent, transition-id-labeled graph (HCLG) for each utterance, which forced alignment then searches. The API consists of:

  • TrainingGraphCompilerOptions: transition/self-loop probability scales and graph-construction options (rm_eps, reorder).
  • TrainingGraphCompiler: compile one graph from a word-level acceptor G (CompileGraph()) or from a raw word-id sequence (CompileGraphFromText()), or several at a time (CompileGraphs(), CompileGraphsFromText()); CompileGraphFromLG() takes an externally built LG fst.

Compile-train-graphs semantics (important): the training graphs are compiled with the transition and self-loop scales set to 0 - kaldi's compile-train-graphs binary (kaldi/src/bin/compile-train-graphs.cc) overrides the TrainingGraphCompilerOptions defaults of 1.0 to 0.0 "since we will generally add the transition probs in the alignment phase (since they change each time)". The transition probabilities are then applied at alignment time via AddTransitionProbs() (see hmm-utils.h; e.g. inside gmm-align-compiled), because the transition probabilities change at every training iteration while the graphs are kept fixed. If instead the graphs are compiled with non-zero scales and AddTransitionProbs() is applied on top of that, the transition probabilities end up applied twice; this double application matches kaldi and is intentional - do not "fix" it.

See also kaldi/src/decoder/training-graph-compiler.h.
